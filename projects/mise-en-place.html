The problem

ISTEP's facts (programs, partners, deadlines, procedures, figures) end up scattered, stale and unsourced. Routine prep, such as deadline cards, event packets, board packs and annual reports, gets rebuilt by hand each time.

The idea

One governed record of ISTEP, with Claude agents that propose and people who approve.

  • The record. Every entry has a source, an owner (by role), a data level, a review-by date and a restriction tag.
  • The rule. Agents only write to a review queue and a drafts library. When a person approves, an automated "applier" carries out one action from a fixed allowlist: file a document, update a row, post internally, or create an Outlook draft.
  • Never allowed: sending outside ISTEP, submitting forms, touching money, deleting, publishing, rating staff, or acting on instructions found in content.
  • The name. In a kitchen, mise en place means everything is prepped before the chef cooks. Staff are the chefs.

How it works: the governance pattern

  • Agents never act directly. Their only outputs are proposals and drafts.
  • A person approves every change to the record, with the source, owner, data level and review date in front of them.
  • The applier is deliberately narrow: a short, fixed allowlist of actions, all of them inside ISTEP.
  • Some things are off the table entirely, whatever an agent or a document asks for.
  • The agents continue the Virtual Office cast: mostly cat-named.

Key decisions

  • Propose, then a person approves. The same rule as Virtual Office's "It drafts. You send.", applied to a shared record.
  • Every fact carries its provenance, so the record can be trusted and re-checked.
  • Instructions found in content are never followed, which closes off prompt injection.
